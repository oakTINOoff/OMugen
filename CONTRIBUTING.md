# Contributing to OMugen

Thanks for helping make OMugen the best way to play MUGEN games. Bug reports from real
games are the most useful contribution of all.

## Reporting a problem

[Open an issue](../../issues/new/choose) with:

- **What happened and what you expected**, step by step from starting the game.
- **The game**: which MUGEN game, and whether it works in MUGEN 1.1.
- **The OMugen version**, shown at the bottom of the main menu (for example
  `nightly - 2026.10.06`, or a release tag).
- **The log**: the newest file in the game's `save/logs` folder.
- For **controller** problems: `save/logs/controllers.txt`, and which pads you use and how
  they're connected (USB, Bluetooth, DS4Windows or Steam Input on or off).
- For **characters or stages** that break: run `OMugen.exe -doctor` in the game folder and
  attach `save/doctor/report.html`, or name the files and where they come from.

Please don't attach copyrighted game content; a name and a link are enough.

## Working on the code

See [BUILDING.md](BUILDING.md) to build and test.

**Where things are**

- `src/omugen_*.go`, `src/mugen_*.go`, `src/mugenjoy/`: OMugen's own engine code (drop-in
  support, `mugen.cfg` controls and controllers, loading, smooth high refresh rates, the
  built-in screenpack, Doctor, `-newgame`).
- The rest of `src/` is the engine core OMugen builds on. Keep changes there small and
  explain them; prefer adding OMugen code in its own files.
- `external/script/`: the Lua menus (`omugen_hud.lua` is the controller indicator).
- `tools/`: the art generators and helper tools. `templates/newgame/`: what
  `-newgame` creates.

**Rules of thumb**

- **MUGEN compatibility comes first.** A MUGEN game must play the way it does in MUGEN 1.1;
  new behavior goes behind an option unless MUGEN would do the same.
- **Never write into a game's folder** except `save/` (and `mugen.cfg`, only when the
  player changes settings, after a backup).
- **No third-party art or sound.** Everything OMugen ships is generated by `tools/` (or is
  a font with its license in `font/`).
- **Don't commit generated files** (`.gitignore` lists them): the build makes them.
- **Go 1.20 language level** (`go.mod`): no `min`/`max` builtins, and never keep a pointer
  to a `range` loop variable.
- `gofmt` clean, `go vet ./tools/...` clean, and `go test ./src ./src/mugenjoy` passing.
- Add a test when you fix a bug that a test can catch.

**Commits**

- The subject says what changed for the player, in plain words, under about 70
  characters: `Controller light bars show the player's color`.
- The body explains why, what you tested and anything surprising.
- One topic per commit.
