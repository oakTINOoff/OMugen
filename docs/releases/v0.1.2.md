Controllers that just work in every game, and fixes from a full review.

## Install

Download **`OMugen-v0.1.2-windows.zip`** below, unzip it and copy `OMugen.exe` into your
MUGEN 1.1 game folder, next to `mugen.exe` (replace the old one if you have it).

> Windows may warn that the app is unrecognized, because the exe isn't signed yet:
> click **More info**, then **Run anyway**.

## What's new

- **Your pad layout follows you.** A game's joystick settings are numbered for the
  controller they were set up on, so on another kind of controller they can land on the
  wrong buttons, or on the triggers, which read as held: menus that scroll by themselves,
  moves on the wrong buttons. When that happens, OMugen now uses your own layout for that
  kind of controller (PlayStation or Xbox): the first one you played with in a game where
  it fits, or the last one you saved in Options. It's kept in
  `%LOCALAPPDATA%\OMugen\pad-layouts.ini`, never in a game folder. Games whose own layout
  fits your controller keep it.
- **A better standard layout** for when you have none yet: D-pad and left stick to move,
  X Y Z on Square Triangle R1, A B C on Cross Circle R2, MUGEN's Start (energy charge in
  many games) on L1, and the pause menu on Options. Xbox pads get the same positions.
- `save/logs/controllers.txt` says which layout each player has and why.
- The exe is named plain **OMugen** in Windows (Task Manager, volume mixer, a program added
  to the NVIDIA app).

## Fixes

- Command-line options for one session (`-nosound`, `-setvolume`, `-ailevel`, `-windowed`)
  were written into the game's `mugen.cfg` at the next settings save.
- Clearing a button in Options > Controls on a replacement layout now sticks.
- `Time = 0` in `mugen.cfg` is ignored instead of ending every round at once.
- A new game made on Linux gets the `lib` folder it needs to start.

`SHA256SUMS.txt` lists the checksums of the downloads.
